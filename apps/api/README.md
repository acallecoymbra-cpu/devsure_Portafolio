# DevSure API

Minimal NestJS foundation for DevSure Phase 0.

## Run

```powershell
# From the repository root:
pnpm install
Set-Location apps/api
Copy-Item .env.example .env
pnpm run start:dev
```

The API is available at `http://localhost:3001/api/v1` and Swagger at
`http://localhost:3001/docs`.

## Verification

```powershell
pnpm run lint
pnpm run typecheck
pnpm run test:unit
pnpm run test:integration
pnpm run build
```

Database changes use the independent TypeORM CLI:

```powershell
pnpm run migration:run
pnpm run migration:revert
pnpm run seed:technologies
```

SQLite runs with `synchronize: false`; use migrations for schema changes.

## Technology catalog persistence

`seed:technologies` is an explicit CLI command. It runs pending migrations and
upserts the approved 41-item catalog by slug without deleting other records.
There is no public seed endpoint.

The technology repository keeps filters parameterized and uses portable
`LOWER`, `COALESCE` and `LIKE` expressions. UUIDs are generated by TypeORM in
the application, statuses are `varchar` values guarded by checks, and no
driver-specific arrays or error codes are used.

The migration targets the current SQLite MVP and therefore declares date
columns as `datetime`. A PostgreSQL migration must map those columns to its
timestamp type; the entity and public contract continue to use JavaScript
`Date` values and ISO 8601 at API boundaries. This is the only known
driver-specific schema mapping in this slice.
